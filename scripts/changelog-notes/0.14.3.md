**Class hierarchy is answerable again, and so are eighteen other relationships the map was quietly throwing away.** The AST extractor emits 27 kinds of relationship between the things it finds — one function calls another, a class inherits from a base class, a template extends a layout, a route points at a handler. The step that writes those into the graph knew about eight of them. The table was written on 2026-06-01, the extractor grew to 34 language extractors, and the two were never reconciled. Every edge carrying one of the other 19 was built by a full parse, carried through every merge and resolution pass, and then dropped at the very last step by a lookup that missed followed by a bare `continue` — no warning, no counter, nothing in any log. `ops:inherits` and `ops:extends` occur in no map on any tree, which means "what does this class inherit from" has been unanswerable in every object-oriented language base parses, for every user, since June. Asking got you an empty result rather than an error, so the map looked complete and simply was not. On the trees measured here the recovery is 31 edges on one and 109 on another, all of them relationships that were found and then discarded.

The two lists cannot drift apart again, because there is only one list now. `scripts/ast/relations.py` holds the vocabulary and both the extractor and the serialiser import it, the same way the file-extension set is derived from the parser table rather than typed out beside it. A relation the vocabulary does not carry no longer vanishes: it raises, naming the relation and the file to add it to, at the point of serialisation and again at the extractor's merge seam where the source file is still known. Adding a relation is one line, and its `ops:` predicate is derived from its name rather than written a second time, so a predicate cannot disagree with the name it belongs to.

Four of the 27 names are never written down anywhere in the extractor, which is why three separate attempts to count them by searching for text returned 24, 25 and 26. One arrives through a function that passes its argument along; one is built by string interpolation from a fixed set of helper names and appears as a literal in no file; two are conditional expressions. The set is now read out of the extractor's own syntax tree, and the check that does it publishes what it counted over — every enumeration path with its size, the total slots visited, and a closing line stating the figure is a floor rather than a closed set, because a bare number invites the reader to argue with the number when the thing to examine is the method. A relation the extractor can emit but the vocabulary does not carry fails the build.
