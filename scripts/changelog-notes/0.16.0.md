**Developer mode is off after the update, and one command turns it back on.** Every installer from 0.7.0 to 0.15.2 wrote `[devmode] enabled = true` into `~/.base-gbl/base.toml`, so Claude ended every reply with a DEVMODE block whether or not anyone had asked for it. 0.16.0 installs with it off. For anyone whose file still has the installer's line, byte for byte, the upgrade that runs after the first session start on 0.16.0 notes it, and the next session start turns developer mode off and shows the paragraph below before anything else; `base doctor` repeats it for 14 days. A value someone set, by `base config set` or by hand, is left as it is.

> base 0.16.0 turned developer mode off. The 0.15 installer had turned it on for every user, so Claude ended every reply with a DEVMODE block listing the domains and rules base injected. To see what base injects without it: base log matches. To turn it back on: base config set devmode.enabled true (while it is on, base does not update itself). To undo this change: base doctor --restore "~/.base-gbl/base.toml.BAK-<date>-pre-0.16.0"

**Most 0.15 installs reach 0.16.0 through `base update`, not by themselves.** base does not update itself while developer mode is on, and the 0.15 installers turned it on, so those installs show the weekly "base update available" banner instead; running `base update` once brings them to 0.16.0, and from then on, with developer mode off, updates arrive on their own.
